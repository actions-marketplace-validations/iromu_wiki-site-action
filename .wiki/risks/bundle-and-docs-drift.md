# Bundle rebuild and docs drift

Two fragile areas worth knowing before editing.

## The committed `dist/` must be rebuilt and committed

The action executes `dist/index.cjs` (see `action.yml` → `runs.main`), **not**
`src/index.js`. `dist/` also holds the runtime assets the generator reads
(`dist/highlight-themes/` and `dist/style.css`). It is generated by:

```sh
npm run build   # copy-assets.js (themes + style.css -> dist/) + esbuild src/index.js -> dist/index.cjs
```

**Rule:** after changing anything under `src/` (or the highlight theme set),
re-run `npm run build` and commit the new `dist/`. If you skip this, the action
silently runs stale code — your change is live in the source but not in the
bundle, so the deployed site will not reflect it. Do not hand-edit `dist/`.

**Why:** the bundle and assets are committed precisely so the action needs no
install step at run time. That convenience means the committed artifact is the
source of truth at runtime.

**How to apply:** treat `dist/` as build output — regenerate, never edit. The CI
workflow (`.github/workflows/ci.yml`) now enforces this: it runs `npm run build`
and fails on `git diff --exit-code -- dist/`, so a drifted `dist/` cannot be
merged. See [[build-and-dev]].

## Docs vs. the build-only contract (now aligned)

`v2` made the action build-only and removed the `gh-pages` publish step. An
earlier drift — the `package.json` description still read *"…publishes it to
the gh-pages branch"* while the code only built — has since been fixed: the
description now says the action *builds* the `.wiki/` into a static site. The
README body and [[how-it-works]] describe the real flow (build to `out-dir`,
then the consuming workflow publishes via `actions/upload-pages-artifact` +
`actions/deploy-pages`).

**Why it mattered:** a stale one-line description can mislead a reader into
expecting the action to deploy.

**How to apply:** keep the `package.json` description, the README, and the
`action.yml` inputs in agreement with the build-only reality when you change
any of them.

## Related

The smoke test (`test/smoke.js`) is the safety net: it asserts page count,
`[[wikilink]]` resolution, broken-link detection, asset presence, nested-page
`../` asset roots, and source-chip URLs. Keep it green — it is the only test.
